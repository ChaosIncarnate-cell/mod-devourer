# SQL: install and uninstall the Devourer (class 10)

The worldserver applies `db-world/` and `db-characters/` by itself, like any module's SQL (the module must be in
the build's module list). `uninstall/` sits outside those folders so it is never applied automatically.

## Install

1. Core patch applied (`core-patch/`), module built.
2. **Generate the DBC-derived rows** (once per install, and again after the server's `dbc` files change):

   ```
   python tools/build_class_dbc_sql.py --dbc <server>\data\dbc
   ```

   It writes `db-world/2026_09_30_05_devourer_class_dbc.generated.sql`. That file copies Blizzard rows, so git
   ignores it (hard rule 2). It also stops with an error if an id the Devourer uses is already taken in the DBCs.
   The client patch tool (`tools/client/`, task 004) writes the same file from the client's DBCs, plus
   `_06_devourer_coa_looks.generated.sql`; after building the client patch this step is already done.
3. Start the worldserver. It applies the files below in name order and remembers them in `updates`.

### Where the class data comes from
Nothing Blizzard-made is committed. Class 10 copies the warrior at install time:
- `player_class_stats` and the `gt*` tables (crit, regeneration, combat-rating scalars) come from the warrior rows
  already in the database. The stock class-10 `gt` rows are unusable (every rating scalar is 0, melee crit
  0.01 per agility), so they are overwritten. The originals are saved first in `devourer_backup_gt`, and the
  uninstall puts them back.
- `SkillRaceClassInfo`, `SkillLineAbility` and `CharStartOutfit` are not in the database. The generator reads
  them from the DBC files.

### Talents
In 3.3.5a each talent tier opens only after 5 points in that tree, and both the server and the client check
this. The Glutton's seven CoA talents cannot fill that on their own, so each tree has 5-rank **placeholder
talents with no effect** (spells 9100050-9100069: Iron Stomach, Deep Hunger, Fluid Flesh, Swelling Brood):

| Tier | Glutton (tab 900) | | |
|---|---|---|---|
| 0 | Iron Stomach (5) | Quick Devour | Devour Whole |
| 1 | Deep Hunger (5) | Feast (needs Quick Devour) | Regurgitate (needs Devour Whole) |
| 2 | | Stretched Gut | |
| 3 | | Digested: Thick Hide (needs Stretched Gut) | Digested: Bile Coating (needs Stretched Gut) |

On CoA, Thick Hide and Bile Coating were a choice of one. 3.3.5a has no choice groups, so both can be taken for
now. Skinchanger (901) and Brood (902) have only their placeholder until they get real talents. The module picks
the spec from the tree with the most points and teaches each spec's identity passive itself.

### From the client patch tool (task 004)
- The Sethrak's own look (display 200004, model 402214) and the Sethrak camp's looks (80018, 80305, 280018).
  The Twinfangs serpents too (991040, 991045). On CoA these rows were in the client's own DBCs, so
  `tools/client/build_client_patch.py --coa ...` copies them from there into the client patch and into
  `_06_devourer_coa_looks.generated.sql`. Without that file the worldserver logs missing-display errors for the
  creatures that use them (9101001-9101002, 9101101-9101102), and a Sethrak-shaped Devourer has no model.

### Not here yet
- A `PowerDisplay` row. Not needed on the server: the power bar is rage because `ChrClasses.DisplayPower` = 1.

### Left out from the CoA files
- The CoA mount pack (`2026_09_27_00_devourer_models.sql`, "mountsADDING": dragonhawks, drakes and a mount
  trainer). It is not part of the Devourer, and its spells 9100500+ sat inside the Devourer's spell range.
- CoA-only rows: `ascension_custom_class_spell`, the old class 20's `playercreateinfo_spell_custom`, the
  `playercreateinfo_item` idol (the module hands the idol out), and the one-off `character_spell` cleanup.

## Uninstall

With the worldserver stopped, characters first:

```
mysql acore_characters < data/sql/uninstall/characters.sql
mysql acore_world      < data/sql/uninstall/world.sql
```

`characters.sql` turns every Devourer into a warrior. It keeps race, level and gear, and flags the character to
reset spells and talents at its next login. It removes the Devourer's spells, talents, auras, cooldowns and action
buttons, and the idols (from bags, bank and mail), then drops the module's tables. `world.sql` deletes every row
by the id ranges above, restores the `gt` rows from `devourer_backup_gt`, and drops the module's tables last.
Both also delete their files' rows from `updates`, so a reinstall runs them again. Then remove the module folder
(and revert the core patch, if wanted).

Checked in a cloud session against the azerothcore-wotlk `7f12e89` database (base + updates, MySQL 8.0):
- Every install file runs twice without errors.
- Install then uninstall leaves both databases identical to a dump taken before the install (`mysqldump` diff
  empty).
- A test Devourer was converted as described, and a warrior next to it was untouched.
